# GitHub Wiki 组织规范

本文件定义 Wiki 的页面命名、导航、链接和更新规则。

## 目录结构（在 GitHub Wiki 本地克隆中）

```text
Home.md              领域总览 + 分级学习地图
_Sidebar.md          完整导航树
_Footer.md           版权/反馈/更新说明（可选）
_META.md             Wiki 状态：层级、页面清单、更新日期、changelog
L0-...md             概念启蒙页
L1-...md             入门页
L2-...md             进阶页
...
```

说明：实际文件名就是页面标题，避免使用斜杠、空格用短横线代替；层级由 `L0-`、`L1-` 前缀表达，层级树由 `_Sidebar.md` 表达。

## 页面命名规则

- 前缀：`L0-`、`L1-`、`L2-`、`L3-`、`L4-`。
- 主体：简短、描述性强、无歧义，例如 `L1-Git-分支与合并`。
- 只使用中文、英文字母、数字、短横线；不要用空格、下划线、斜杠、点号。
- 同一个页面在 `_Sidebar.md`、正文链接、`_META.md` 中必须使用完全相同的名称。

## Home.md 的职责

- 一句话说明这个知识库讲什么、给谁看。
- 给出完整的分级学习地图：L0-L4 各自的目标、主要页面、完成标准。
- 说明本知识库采用的分级标准（通用五级或行业标准映射）。
- 链接到 `_Sidebar.md` 中已有的页面；尚未生成的层级标注为“规划中”。

## _Sidebar.md 的职责与格式

```text
**Home**

**L0 概念启蒙**
- [[L0-领域是什么]]
- [[L0-如何安装与运行Demo]]

**L1 入门**
- [[L1-第一个真实任务]]

**规划中**
- L2 进阶（待生成）
- L3 高级（待生成）
- L4 专家（待生成）
```

规则：侧边栏要反映真实完成状态；“规划中”只列层级名，不创建死链。

## _META.md 的职责

用于记录 Wiki 状态，方便下次更新时快速盘点。建议包含：

- 领域名称。
- 分级标准与映射说明。
- 页面清单：页面名、层级、状态（已完成 / 规划中）、最后更新日期。
- changelog：日期、变更内容、来源。

示例：

```text
# Wiki 状态

- 领域：Git
- 分级标准：通用五级模型
- 当前进度：L0 已完成，L1 规划中

## 页面清单
- [x] L0-Git是什么与第一次提交（2026-01-01）
- [ ] L1-Git分支与合并

## changelog
- 2026-01-01：创建 Home、_Sidebar、L0 页面。
```

## 链接规则

- 正文内互链优先使用 `[[页面名]]`。
- 每页都要有“上一页 / 下一页 / 返回 Home”导航。
- 不创建指向不存在页面的链接；规划中的层级只出现在 Home 和 _Sidebar 的“规划中”区域。
- 外部资料使用普通 Markdown 链接，并注明访问日期。

## 更新规则（持续更新）

- 更新已有页面时使用“合并更新”：保留仍有效的内容，只替换过时部分，不整页覆盖。
- 每次更新都要在页面底部“更新日志”追加一行，并在 `_META.md` 的 changelog 追加一条。
- 更新后必须重新检查 `_Sidebar.md` 是否仍然完整，避免出现孤立页面或死链。
- 首次生成只生成 L0 导论；后续生成下一级前，先确认上一级页面已完整。
