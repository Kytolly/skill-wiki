# 分级方案与目录组织

本文件定义 skill-tutorial-wiki 的分级规则。原则：**分级服务于教程任务，不硬套固定五级**。

## 默认：按任务自定

不再默认使用 L0–L5。为每个教程任务选择合适的分级：看任务需要几次"能力台阶"。

## 选择流程

1. 判断能力台阶数：一般 3–5 级为宜；过多拆子级，过少则合并。
2. 选命名方案（可混用，但要一致）：
   - 阶段式：`basics / practice / tuning / deployment`
   - 能力式：`intro / fundamentals / advanced / expert`
   - 项目式：`setup / task1 / task2 / optimize`
   - 通用五级：`L0 / L1 / L2 / L3 / L4`（仅在确实匹配时用）
3. 为每级写一句"学完后能做什么"，作为该级目录的完成标准。
4. 确认后写入 `_META.md`，并在 `Home.md` 说明分级依据。

## 目录硬约束（关键）

- **同一分级 = 同一目录**：`page/<grade-slug>/`。
- grade-slug 用 ASCII 小写短横线（`L0`、`basics`、`02-advanced`）；中文显示名在 `_Sidebar.md` / `mkdocs.yml` / `_META.md` 中映射。
- 页面文件名只表达主题（如 `Git是什么与第一次提交.md`），**不再带 `L0-` 前缀**——目录已经表达分级。
- 导航（`_Sidebar` 与 mkdocs `nav`）按分级目录生成，便于浏览。

示例：

```text
page/
├── Home.md / _Sidebar.md / _META.md / _Footer.md
├── basics/                     # 入门
│   ├── Git是什么与第一次提交.md
│   └── 安装与配置.md
├── practice/                   # 实战
│   └── 分支与合并.md
└── advanced/                   # 进阶
    └── 冲突解决与回退.md
```

## 学习曲线约束（必须遵守）

- 每级只引入 5–7 个新核心概念；其余是上一级复习或本级展开。
- 每页开头列前置知识，且前置知识要能链接到已有页面。
- 出现未解释术语：在本页解释或链接到解释页，不允许孤立术语。
- 跨度太大时拆子级（`practice/` → `practice/basic/`）或多页；层级跨越不能陡峭。
- 子级写清与相邻层级的关系。

## 行业标准映射

领域有公认能力标准时优先映射到该标准，并在 Home/_META 说明映射关系；没有公认标准时自定分级并说明依据。常见映射参考：

| 领域 | 常见标准 | 建议映射 |
|------|----------|----------|
| 编程语言/软件工程 | 初级/中级/高级/架构师/专家 | 4–5 级 |
| 云厂商 | Foundational/Associate/Professional/Specialty | 4 级 |
| 数据与 AI | 入门/实践者/高级/专家 | 4 级 |
| 外语 | CEFR A1–C2 | 按 CEFR |
| 信息安全 | 入门/中级/高级/专家 | 4 级 |

## 默认起始与目标

- 用户未指定时，默认只生成最低一级的导论（主题是什么、核心术语、安装/配置、跑通 demo、下一步）。
- 后续按用户显式提示推进（继续下一级、补全某级等）。
