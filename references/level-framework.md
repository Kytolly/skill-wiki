# 分级模型与行业标准映射

本文件定义 `skill-tutorial-wiki` 的层级划分规则。SKILL.md 只引用这里的结论。

## 默认五级模型

| 层级 | 定位 | 读者完成后能做什么 | 典型行业映射 |
|------|------|--------------------|--------------|
| L0 概念启蒙 | 零基础建立心智模型 | 说清这个领域是什么、解决什么问题、能跑通一个官方 demo | 科普 / 导论 / 新手体验 |
| L1 入门 | 会做最小真实任务 | 独立完成最小可用任务，理解基本流程与常用工具 | 初级 / Associate / A2 |
| L2 进阶 | 能处理常见任务 | 理解原理与边界，会调试、选型，能应对常见变化 | 中级 / Professional / B1-B2 |
| L3 高级 | 能设计与权衡 | 做架构设计、性能优化、复杂系统与异常处理 | 高级 / 架构师 / C1 |
| L4 专家 | 能看穿本质并创新 | 追踪前沿、方法论输出、指导他人、处理罕见问题 | 专家 / Specialty / C2 |

## 学习曲线约束（必须遵守）

- 每一级只引入 5-7 个新的核心概念；其余内容必须是上一级的复习或本级的展开。
- 每页开头必须列出前置知识，并且前置知识都要能链接到已有 Wiki 页面。
- 出现未解释的术语时，二选一：在本页解释，或链接到解释它的页面。不允许出现孤立术语。
- 判断是否要拆分：如果某一级预计需要 10 个以上页面，或读者需要同时掌握两个以上的新体系，就拆成子级（如 L2a、L2b），或拆成更多独立页面。
- 层级跨越不能陡峭：从 Ln 到 Ln+1，新概念数量翻倍或难度明显跳升时，必须增加过渡页或中间层级。

## 子级命名

- 优先使用 L0 / L1 / L2 / L3 / L4。
- 需要细分时使用 L2a、L2b；不要发明没有解释的命名。
- 子级必须写清它与相邻层级的关系，例如 L2a 结束于哪些能力，L2b 从哪些能力开始。

## 行业标准映射

如果目标领域存在公认的能力标准，优先映射到该标准，并在 Home.md 中说明映射关系。

| 领域 | 常见标准 | 建议映射 |
|------|----------|----------|
| 编程语言 / 软件工程 | 初级 / 中级 / 高级 / 架构师 / 专家 | L1-L4 |
| 云厂商（AWS / Azure / GCP / 阿里云） | Foundational / Associate / Professional / Specialty | L1-L4 |
| 数据与 AI | 入门 / 实践者 / 高级 / 专家 | L1-L4 |
| 外语 | CEFR A1-C2 | L1-L4（L0 可对应 A0 预备） |
| 信息安全 | 入门 / 中级 / 高级 / 专家 | L1-L4 |

没有公认标准时，直接使用默认五级模型，并在 Home.md 说明“本知识库采用通用五级划分”。

## 默认起始与目标层级

- 用户未指定时，默认只生成 L0 导论。
- L0 导论必须覆盖：领域是什么、解决什么问题、核心术语、如何安装/配置、如何运行一个已有的 demo、下一步学什么。
- 后续按用户显式提示或按“上一级已完整、再生成下一级”的规则推进。
